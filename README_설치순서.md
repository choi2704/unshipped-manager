# 미출고·반송예정 공동 관리 v4 — 초보자 설치 순서

기존 GitHub Pages를 그대로 사용하면서 Supabase에 데이터를 저장합니다. Vercel은 필요하지 않습니다.

## 첫 설치 준비

1. 기존 GitHub Pages 프로그램의 **백업 / 복원 → 전체 데이터 JSON 백업**을 내려받아 보관합니다. 중요: 기존 개인 브라우저 데이터는 자동으로 클라우드로 옮겨지지 않습니다.
2. https://supabase.com/dashboard 에서 프로젝트 생성. 프로젝트 이름은 예: `unshipped-manager`.
3. **SQL Editor → New query**에서 `SUPABASE_처음한번_실행.sql` 전체를 붙여 넣고 Run.
4. **Project Settings → API Keys** 또는 **Connect**에서 `Project URL`과 **publishable key** (또는 예전 형식 `anon` 키) 복사. **service_role / secret 키는 절대 복사하지 마세요.**
5. `config.js`를 메모장으로 열고 URL 및 공개용 키 입력 후 저장.
6. GitHub 저장소 `choi2704/unshipped-manager`에 `index.html`, `config.js`, `vendor/pako.min.js`를 업로드하고 Commit. SQL 파일은 GitHub에 둘 수 있지만 실제 고객 데이터, 비밀번호, secret 키는 업로드하지 마세요.
7. 기존 GitHub Pages 주소 `https://choi2704.github.io/unshipped-manager/` 에 접속. 로그인 화면에서 **직원 계정 신청**으로 우선 본인 계정을 생성. Supabase Auth 설정에 따라 이메일 인증 링크를 확인해야 합니다.
8. 첫 관리자 계정 승인: Supabase **SQL Editor**에서 다음 문장을 실행합니다. **이메일은 실제 가입한 본인 이메일로 바꿔야 합니다.**

```sql
update public.members
set approved = true, is_admin = true
where email = '내가_가입한_이메일@example.com';
```

반드시 본인의 이메일을 넣고, 의도한 1명만 관리자 승인되었는지 확인하세요. 브라우저에서 로그아웃 후 다시 로그인하면 관리자 메뉴가 나타납니다.

## 직원 추가

1. 직원이 동일한 페이지에 접속해 **직원 계정 신청**을 합니다.
2. 이메일 인증 후 계정이 생성되면 관리자에게 알려 줍니다.
3. 관리자는 **직원 승인** 메뉴에서 해당 직원 이메일을 확인하고 승인합니다.
4. 직원이 로그인하면 공용 주문 목록과 변경 기록을 함께 볼 수 있습니다.

## 엑셀 업로드

- 미출고 탭 → **사방넷 미출고 엑셀 올리기**
- 반송예정 탭 → **사방넷 반송예정 엑셀 올리기**
- `물류메세지` 필터로 자동 선택 또는 검색 결과만 내려받은 파일이라면 `전체 행 가져오기`를 선택합니다.
- 업로드 미리보기를 확인한 뒤 선택한 주문만 등록합니다.
- 중복 여부는 현재 목록을 기준으로 확인하며, 다른 팀에서 동시에 같은 엑셀을 올리는 경우에는 **중복 등록 가능성**이 있으므로 운영 담당자가 업로드 담당을 한 명으로 정하고 수시로 점검하세요.

## 기존 개인 데이터 옮기기

- 관리자 계정으로 로그인 → **백업 / 복원 → 기존 개인시험판 JSON 가져오기**.
- v3 JSON 파일을 선택하면 같은 주문번호+상품명+판매처 항목을 건너뛰고 추가합니다.
- 개인정보가 포함된 JSON 파일은 회사 승인 없이는 옮기지 마세요.

## 운영 시 주의

- GitHub Pages에서 보여주는 `config.js` 공개키는 **공개용 키**입니다. 보호는 공개키 숨김이 아니라 **Supabase 인증과 RLS 정책**이 담당합니다.
- 직원 중 승인된 사람은 현재 모든 주문을 읽고 수정할 수 있습니다. 부서별 세밀한 권한은 후속 버전에서 추가할 수 있습니다.
- 기록은 서버의 감사 로그에 남지만 정기 백업 정책은 별도로 필요합니다.
- 고객 개인정보를 실제 업무에 입력하기 전에 사내 보안·개인정보 처리 기준을 확인하고 테스트 계정으로 먼저 검증하세요.
- 로그인하지 않은 사용자는 RLS로 데이터 조회·수정이 차단됩니다. 직원별로 비밀번호를 공유하지 마세요.
- 첫 연결 및 팀 테스트 시 **가명/테스트 주문만** 사용하세요.
- 5,000건 이상 규모에서는 페이지 단위 조회로 개선이 필요합니다.
